## 1.0.0-rc.8

- **Dial-back stability & auto-recovery (CF-40):** Release the peer's dial-back handshake permit once the first request frame arrives (instead of holding it across the whole `rustc` job), so large peers (e.g. 32 slots) can serve more than 16 concurrent dialed-back jobs. Bound outgoing dial-back handshakes per peer (4) and overall (6, per-peer permit first) without blaming local queue waits on the peer, require 2 consecutive connection failures before pausing an already-working peer, re-probe online `FAILING` peers automatically after the 60 s pause, and reset `FAILING` on reconnect after being offline.
- **Proc-macro builds with pipelining (CF-41):** Promote pipelined transitive `.rmeta` dependencies in `depgraph` to their sibling `.rlib` files when compiling `--crate-type proc-macro` crates remotely, avoiding `required to be available in rlib format` failures.
- **Build-script probes stay local (CF-42):** Classify build-script compiler probes (`--out-dir` or primary input under `OUT_DIR`, e.g. `anyhow`, `thiserror`, `proc-macro2`, `autocfg`) as always local so expected probe errors are not sent to peers or counted as `RemoteCompileErrorRetry`.
- **Hardcoded local paths in `OUT_DIR` (CF-43):** Detect generated `OUT_DIR` `.rs` files that embed literal submitter paths (such as `khronos_api`) and run them locally instead of failing on a peer.
- **Clean-build `depgraph` & `doctor` accuracy (CF-44):** Raise `MAX_IPC_UNAUTHENTICATED` from 16 to 128 to match `MAX_JOBS`, write `node-unresponsive` only on a real 30 s silence timeout (not an immediate close/EOF), drain and FIN the IPC socket cleanly after `LocalDone`, count `unknown_dep.*` only on actual `UnknownDependency` fallbacks, ignore 0-byte `.rmeta` files from `cargo clippy --all-targets` `--test` targets in `crabfarm doctor`, and clarify incremental workspace / `clippy` crates in the `doctor` hint.
- **Observability (CF-45):** Log `TooLarge`, embedded local paths in `OUT_DIR`, failed job-connection causes (rate-limited for refusal floods), and the first 64 distinct `UnknownDependency` paths at `INFO` level; show a `CRABFARM_LOG=debug` + `node.log` path hint in `crabfarm doctor` whenever a warning or problem is reported.

## 1.0.0-rc.6

First release, 1.0.0 (Windows to Windows farms).

- **Binaries:** `crabfarm` (`node`, `farm create|invite|join|leave`, `cargo <args>`, `status`, and the rustc wrapper mode that cargo calls), `crabfarmd` (the node without a console window) and `cargo-crabfarm` (`cargo crabfarm build` = `crabfarm cargo build`).
- **Farm identity:** a farm CA created on the first machine; machines join with a one-time join code (valid 10 minutes, single use) and get their own certificate.
- **Transport:** mutually authenticated TLS 1.3 between farm members only; no plaintext or anonymous mode. The local wrapper talks to the node over loopback with a per-start random token.
- **One-way networks (CF-34):** when this machine cannot connect to a peer (a notebook on a work VPN, NAT) but the peer can connect here, job and cache connections are opened by the peer on request (dial-back over the existing control connection). `crabfarm status` shows per peer how jobs reach it (`direct`, `dial-back`, `FAILING`) and warns when neither works. Protocol 7.
- **Distribution:** library crates compile on whichever machine has free capacity; linking, build scripts and anything unusual stay local, so the output matches a local build.
- **Cached inputs:** blobs kept on other machines are encrypted with the submitting machine's key; job sandboxes are deleted when the job ends.
- **Cargo pipelining:** metadata and dep-info results are relayed as soon as they exist, so cargo can start dependent crates before the full build finishes.
- **Hardening:** peer-supplied paths, toolchain specs and job specs are validated; the executor uses an environment allowlist and size caps; a job's whole process tree is killed on timeout; outputs that embed the sandbox path are rerun locally; connection, blob and discovery limits and idle timeouts guard against misbehaving peers; join codes, keys and environment values never appear in logs.
- **Install:** a per-user Windows setup (`crabfarm-<version>-setup.exe`: optional PATH entry and start at sign-in, no admin rights) and `install.sh` for macOS and Linux (checksum-verified, no sudo); `crabfarmd`, the node without a console window; `crabfarm service install|uninstall|status`, `crabfarm path add|remove`, `crabfarm node --stop`; `crabfarm enable|disable [--global]` so plain `cargo build` uses the farm (`enable` writes to the workspace root and says which folder it chose; an existing wrapper such as sccache, also one from a parent folder or `CARGO_HOME`, is kept for local compiles and restored by `disable`; a `RUSTC_WRAPPER` in the environment is warned about; a project config that git tracks is refused unless `--force`, since it would carry this machine's path into commits; new tables go below the comments that close the file); a step-by-step guide (`docs/GETTING-STARTED.md`, https://crabfarm.renner.dev/guide.html).
- **Publication:** MIT license, release archives for Windows, Linux and macOS (x86_64 and aarch64) with checksums and build provenance, a website at https://crabfarm.renner.dev.
- **Fails safe:** a missing peer, missing toolchain, network error or unsupported flag runs the job locally; fallbacks are counted in `crabfarm status`.
- **Setup and uninstall (CF-27):** a running node is stopped and the result checked; programs that cargo or rust-analyzer still run are renamed aside instead of failing the update; an uninstall that cannot remove files keeps its Installed apps entry, says so and exits non-zero (silent mode); the uninstaller removes a global `crabfarm enable --global` entry that points at this install.
- **Environment never-list (CF-27):** every `GIT_` name except a short list of build-script data names, plus C runtime, locale, allocator, Visual Studio/SDK discovery and OpenSSL configuration variables.
- **Compile cache (CF-28):** a built-in cache of rustc results, local and farm-wide, on by default (`cache = true`, `cache_entries_max_gb = 10`). Every successful remote-eligible compile, whether it ran here or on a peer, is stored under a BLAKE3 key over the compiler, the arguments with their client paths, the forwarded environment and the hash of every input; the next time the same invocation comes up its files are restored atomically and its warnings replayed, and the dep-info is checked like a remote result's, so cargo sees a normal run. A miss asks the online peers (one round trip, 300 ms limit) before compiling. Entries are encrypted with a farm-wide key that `farm create` makes and `JoinAccepted` hands out (**protocol 6**: install the same version on every machine); results from `sensitive` and `local_only` paths are never cached, nor are failed compiles, nor crates that read a file or variable outside what the key covers. A result of a local run is stored when no proc macro is in the crate's `--extern` closure; with one, only a result of a remote run is stored (the peer's sandbox held only the shipped files) and a local result never is, so a proc macro that reads a file outside the package directory is not served stale (`crabfarm cache stats` shows the count of local results not cached; a macro that reads an outside file only when it exists is not detected). Only built-in targets (`rustc --print target-list`) are cached, and a job under `sensitive` or `local_only` leaves nothing in the cache store. The wrapper sends its protocol version with `IpcAuth`; a node refuses another version with an error and the wrapper builds locally. Cache questions use the authenticated control connection (two at a time per peer), and the Apple `*_DEPLOYMENT_TARGET` variables are forwarded and in the key. `crabfarm cache stats|clear`, a cache line in `crabfarm status`, DESIGN section 16 and SECURITY.md describe it.
- **`crabfarm doctor` (CF-38):** checks farm membership, the node, autostart, PATH, a `RUSTC_WRAPPER` in the environment (which makes plain cargo bypass crabfarm), the project's wrapper config, how many of the project's built libraries crabfarm does not know (`UnknownDependency`), and per peer whether jobs reach it; one line per finding with the fix. `--fix` starts the node, points autostart at this install and clears a stale "node did not answer" marker; it never edits PATH, the environment, the firewall or project files. `crabfarm status` now splits `UnknownDependency` into dependencies cargo built without crabfarm and ones that changed since (CF-35).
- **`crabfarm update` (CF-37):** downloads the newest published GitHub release (`--pre`: release candidates too, `--check`: only report) over HTTPS from this repository's release URLs only, checks it against the release's `SHA256SUMS.txt`, and installs it: the Windows setup silently with the current PATH and autostart choices, or the release's `install.sh` into the same folder on macOS and Linux. A node that ran before runs again afterwards. `cargo install` and other installs are told what to do instead.
- **Faster fallback (CF-27):** opening a job on a peer has one 12 s deadline; a peer's addresses are tried at the same time.
