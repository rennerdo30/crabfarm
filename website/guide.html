Getting started

Build Rust projects on your notebook with the cores of your desktop. This takes about ten minutes. Everything is per user: no admin rights, except the Windows Firewall rule in step 4, which only the desktop needs. You need two or more machines you own, on the same network or a VPN, with Rust (rustup) on each.

1. Install on the desktop

  1. Download crabfarm-<version>-setup.exe from the Releases page and run it. SmartScreen may say "unknown publisher" because the file is not code-signed: choose More info, then Run anyway.
  2. Leave both boxes ticked: Add crabfarm to PATH and Start the crabfarm node when I sign in (a background process without a window).
  3. Open a new terminal and check it works:
crabfarm --version

2. Create the farm (desktop, once)

crabfarm farm create --name desktop
crabfarm farm invite

The second command prints one line starting with cf1-, valid for 10 minutes and usable once. If it points at the wrong network address, add --addr 192.168.1.20:47070.

3. Install on the notebook and join

Run the same setup on the notebook (no admin rights needed), then in a new terminal:

crabfarm farm join cf1-PASTE-THE-CODE-HERE --name notebook
crabfarm status

The first line of status should say farm: 1 of 1 peers online.

4. The Windows Firewall question

The first time the node listens on the network Windows asks whether to allow crabfarmd. Tick Private networks only. Answering it needs administrator rights, which a standard user on a managed notebook does not have. If the prompt never appeared, an administrator can add the rule once (admin PowerShell):

netsh advfirewall firewall add rule name="crabfarm" dir=in action=allow program="%LOCALAPPDATA%\Programs\crabfarm\crabfarmd.exe" protocol=TCP localport=47070 profile=private

A notebook that only sends work needs no rule: it connects outward to the desktop. Put accept_remote_jobs = false in its config.toml (step 5 shows where) so it never accepts jobs from others, and add the desktop under peers. To avoid the prompt entirely, also set listen = "127.0.0.1:47070" on the notebook. (Checked in the code; not tried on a managed Windows notebook.)

5. VPN, Tailscale or another network

On one local network the machines find each other. Across a VPN, list the others in %APPDATA%\renner\crabfarm\data\config.toml:

peers = ["desktop.my-tailnet.ts.net:47070"]

Create the join code with that address too: crabfarm farm invite --addr desktop.my-tailnet.ts.net:47070. Settings are read at node start; restart with crabfarm node --stop followed by crabfarm service install.

6. Use it in a project

A. One command, nothing changed

crabfarm cargo build --release
cargo crabfarm build --release   # the same

B. Per project (recommended)

crabfarm enable

Adds rustc-wrapper and jobs (three lines when you already use a wrapper such as sccache, which is kept on its own line) to the .cargo/config.toml of the project, or of the workspace root when you run it in a member (it prints the folder it chose), keeps your comments and other settings, and prints the jobs value it chose with how to change it (crabfarm enable --jobs 40). Plain cargo build, check and test then use the farm. An existing wrapper such as sccache keeps working for local compiles and comes back on crabfarm disable. The file holds the path of crabfarm.exe on your machine, so most people git-ignore it.

C. Everywhere

crabfarm enable --global

Same, in %USERPROFILE%\.cargo\config.toml; undo with crabfarm disable --global. Without a running node, builds simply run locally.

IDE: with B or C, rust-analyzer's background cargo check also runs with crabfarm as the wrapper. If an editor misbehaves, run crabfarm disable in the project. If RUSTC_WRAPPER or CARGO_BUILD_RUSTC_WRAPPER is set in the environment it overrides the config file: enable warns and crabfarm is not used until you unset it.

7. Work repositories

crabfarm sends your project's source to your own machines to compile it. It is encrypted and only farm members can connect, but a peer sees the plaintext source it compiles and runs the proc macros, so every member must be a machine you control. If your employer restricts where code may be copied, check that a second company machine is allowed; a private desktop at home is not.

local_only = ['C:\Work\secret-project']   # never sent to a peer
sensitive  = ['C:\Work']                  # sent, but peers delete it after each job

local_only is the strong setting: crates whose source or manifest lies under those folders are never sent (public crates.io dependencies may still be). sensitive is weaker: the peer still reads the source while compiling, it just does not keep it. For a work notebook, local_only = ['C:\Work'] on the notebook keeps all work code at home while the notebook can still help build for the desktop.

8. Check that it works

crabfarm status
  • remote ok counts compiles a peer did for you; it should grow when you build.
  • local counts compiles that ran here, with the reason. Linking, build scripts and the final binary always run locally.
  • remote failed counts jobs a peer could not do, which your machine then redid. A few are normal.

The compile cache. Every library crate crabfarm compiles, here or on a peer, is also kept (default limit 10 GB). When the same crate comes up again with the same compiler, flags, sources and dependencies, the stored result is used and rustc does not run: after cargo clean, after switching branches, and on another farm machine that builds the same project at the same path (the path is part of what rustc prints and writes, so a different path is simply a miss). A crate that uses a proc macro is cached only from a run on a peer, never from a local run. Only built-in targets are cached. crabfarm status shows compile cache: 41 hits (35 local, 6 farm), 3 misses, ....

crabfarm cache stats    # entries and size on disk, hit counters
crabfarm cache clear    # delete everything the cache holds on this machine

In config.toml: cache = false turns it off on this machine, cache_entries_max_gb = 10 sets its size. Nothing under local_only or sensitive is cached.

9. If something is wrong

  • The node is not running: crabfarm service status; crabfarm service install to turn autostart on and start it, or crabfarm node in a terminal to see what it says.
  • Everything runs locally (NoPeer): the machines do not see each other. Check the firewall (step 4), the network, or add peers (step 5).
  • The first build is slow: the desktop may have to install the Rust version your project needs, once.
  • Version mismatch (peer speaks protocol 5, this node speaks 6): install the same crabfarm version on both machines.
  • The log: %APPDATA%\renner\crabfarm\data\logs\node.log holds crate names, sizes and timings, never your code.

10. Uninstall

Run crabfarm disable in every project where you used crabfarm enable first (the uninstaller only removes a global entry that points at this install), then Settings, Apps, crabfarm, Uninstall. It stops the node, turns autostart off and removes crabfarm from PATH. Your farm identity and cache stay unless you tick Also delete my farm identity and cache.

macOS and Linux

curl -fsSL https://github.com/rennerdo30/crabfarm/releases/latest/download/install.sh | sh

No sudo; programs go to ~/.local/bin and the download is checked against SHA256SUMS.txt. Then follow the same steps. crabfarm service install starts the node at login (LaunchAgent on macOS, systemd user service on Linux).
